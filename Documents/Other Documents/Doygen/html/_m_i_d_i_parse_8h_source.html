9// Notes:
10/*
11 MIDI is old and has a different byte order than modern PCs
12 so we have to swap the byte orders around when importing them
13 (big endian)
14
15 The data we want in MIDI in in the 7 bits after the first bit
16
17 Links:
18 http://www.petesqbsite.com/sections/express/issue18/midifilespart1.html
19
20 First parse the header to find if it's a valid MIDI file, then the next two tracks will always be the Time Signature and BPM.
21
22 We have to read everything in the stream sequentially or else it will get corrupted.
23 So even if we get loads of useless data, we won't be using we still need to parse it.
24
25 Running status is a byte that is included in multiple chunks in a track, however becuase of the way midi is optimised it only says
26 it for that first part of the chunk and then we assume it is the same for the chunks following it.
27 We need to look at the left most bit to see if it is a 'status byte' (0) or a 'data byte' (1)
28
29 Status bytes are things like Note On, Note Off,
30 Status bytes = 80 -> EF
31 System messages = F0 -> FF
32
33 Real Time System Events are only used for Live Midi so we can ignore them in the parser.
34
35 General Midi for which instruments are assigned a certain number:
36 https://en.wikipedia.org/wiki/General_MIDI
37
38 Tempo are how many microseconds are in a quarter note. We dived the tempo by 1 million to convert it to seconds.
39 To get it as a'tick' we divide that new number in seconds by a large number (we can just use 24 for now and see what happens).
40 The tick allows us to get an accurate delta time.
41
42*/
